# Proposal

## Why

レシピのフォームは、料理名が空でないことと、数値と URL の形しか確かめていない。説明、材料、作り方、タグ、メモには長さや数の上限がなく、極端に長い入力も保存できる。料理名は161文字以上でデータベースの制約にかかり、調理時間や人数は21億を超えると整数の範囲を超えて、どちらも保存のときにデータベースのエラーがそのまま表示される。レシピノートを作る RPC は名前の上限（画面の50文字）を確かめていない。さらに、タグの入力欄は日本語の変換を確定する Enter でもタグを追加してしまう。入力の上限を決めて、画面とサーバーの両方で守り、エラーを分かりやすく表示する。

## What Changes

UI の変更に加えて、データベースの制約と RPC を変える（マイグレーション）。ルーティングは変えない。

- レシピのフォームに、項目ごとの上限を付ける。超えた場合は保存せず、その欄にエラーを表示する。長い文章の欄には文字数を表示する

  | 項目 | 上限 |
  |---|---|
  | 料理名 | 100文字（必須はいまのまま） |
  | ひとこと説明 | 500文字 |
  | 材料 | 1行100文字、最大50行 |
  | 作り方 | 1行500文字、最大50行 |
  | タグ | 1つ20文字、最大10個 |
  | 調理時間 | 1〜4,320分 |
  | 人数 | 1〜100人分 |
  | 参考URL | 2,000文字。`http://` または `https://` の後ろに続きがあること |
  | メモ | 2,000文字 |

- サーバー側でも同じ上限を守る。データベースの `recipes` に制約を足し、画面を通さない保存でも上限を超えないようにする。料理名も100文字の制約を足す（いまの1〜160文字の制約は残し、100文字の上限を重ねる）
- 既存のレシピは、新しい制約で弾かない（追加の制約は既存の行を確かめない）。ただし、上限を超えている既存のレシピを編集して保存するときは、上限を守る必要がある
- レシピノートを作る RPC `create_group` に、名前の上限（前後の空白を除いて1〜50文字）を足す（名前の変更とそろえる）
- タグの入力欄で、日本語の変換を確定する Enter ではタグを追加しない。上限（20文字、10個）を超えるタグは追加せず、理由を表示する
- AI の下書きを整えるときの上限を、フォームの上限にそろえる（下書きを入れた直後にエラーが出ないようにする）

対象外:

- 既存のデータのうち上限を超えるものの修正
- 入力の上限以外の検証（URL が実在するか、など）
- AI の下書きとレシピノートの名前の変更（すでに上限がある）

影響する動作モード:

- Supabase接続（手元では Supabase Local）: 上限を超えた入力は画面で止まり、サーバーでも保存されない
- デモ: 保存はいまどおりできないが、フォームの上限とエラーの表示は同じように動く

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `recipes`: 「入力の検証」に各項目の上限と、サーバー側でも守ることを追加する。「タグの入力」に、タグの長さと数の上限、日本語の変換を確定する Enter で追加しないことを追加する
- `recipe-note-management`: レシピノートを作るときの名前の上限（1〜50文字、サーバー側でも守る）を追加する

## Impact

- 追加: `supabase/migrations/20261113000000_add_input_limits.sql`（`recipes` の制約、配列の各要素の長さを確かめる関数、`create_group` の名前の上限）
- 変更: `src/features/recipes/components/RecipeForm.tsx`（zod のスキーマ、文字数の表示、エラーの表示、入力欄の `maxLength` と `max`）
- 変更: `src/features/recipes/components/TagInput.tsx`、`IngredientEditor.tsx`、`StepEditor.tsx`（上限、変換中の Enter）
- 変更: `supabase/functions/recipe-draft/index.ts`（AI の下書きを整えるときの上限を、フォームの上限にそろえる。下書きがフォームの上限を超えないようにするため）
- `seed.sql`: サンプルのレシピは上限の内側なので変えない（`npm run db:reset` で当たることを確かめる）
- RLS: 変更なし
- localStorage のデータ形式: 変更なし
- 依存パッケージの追加: なし
- 本番: マイグレーションを本番の Supabase に当てる必要がある
