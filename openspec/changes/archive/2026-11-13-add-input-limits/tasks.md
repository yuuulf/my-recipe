## 3. 確認

- [x] 3.1 `npm run lint` と `npm run build` がエラーなしで通ることを確かめる
- [x] 3.2 Supabase Local の追加画面と編集画面で、各項目の上限を超えると保存されず該当する欄にエラーが出ること、上限ちょうどは保存できること、説明とメモの文字数の表示、材料と作り方の50行で追加ボタンが無効になること、`https://` だけの参考URLが弾かれることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。テスト用のセッションで DevTools Protocol を操作した。上限を超える料理名、説明、メモ、材料と作り方の行で保存を押すと保存されず、各欄に「料理名は100文字以内にしてください。」「材料は1行100文字以内にしてください（1行目）。」などが出る。説明とメモの文字数は「501 / 500」「2,001 / 2,000」と赤く出る。調理時間4,321、人数101、`https://` だけの参考URLは、ブラウザ標準の検証が先に送信を止める（「値は 4320 以下にする必要があります。」など）。上限ちょうど（料理名100、説明500、メモ2,000、参考URL2,000、調理時間4,320、人数100、材料100文字、作り方500文字）は保存でき、DB にもその長さで入った。材料を50行にすると「材料を追加」が無効になる。途中で、材料と作り方と配列全体のエラーが react-hook-form の `root` に入って表示されない不具合を見つけて直した
- [x] 3.3 タグの入力欄で、日本語の変換を確定する Enter ではタグが追加されないこと、21文字のタグと11個目のタグが追加されずメッセージが出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。変換中の Enter（`isComposing`）と `keyCode` 229 の Enter ではタグが追加されず、文字が入力欄に残る。通常の Enter で追加される。21文字のタグは追加されず「タグは20文字以内にしてください。」が出て文字が残る。10個ある状態で11個目は追加されず「タグは10個までです。」が出て、＋ボタンが無効になる
- [x] 3.4 上限を超える既存のレシピ（`psql` で入れる）を開いて表示でき、編集して保存しようとすると該当する欄にエラーが出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。説明が600文字の既存のレシピ（制約を外して入れ、`not valid` で足し直した）は詳細画面に全文が表示され、編集画面でそのまま保存しようとすると「ひとこと説明は500文字以内にしてください。」が出て保存されない
- [x] 3.5 セットアップ画面で、50文字を超える名前は切られずに文字数が赤くなり、作ろうとするとエラーが出て作られないこと、新しいレシピノートを作れることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。セットアップ画面の名前の入力欄の `maxLength` は50。所属している利用者が名前を入れて作ると、作ったレシピノートが開いた
  - 追記: 利用者と相談して、レシピノートの名前の入力欄（セットアップ画面と設定画面）からも `maxLength` を外し、文字数の表示とエラーにそろえた。60文字を貼り付けると、どちらの画面でも60文字のまま残り「60 / 50」が赤く出て、作成・保存を押すと「レシピノートの名前は1〜50文字にしてください。」が出て、レシピノートは作られず名前も変わらないことを DevTools Protocol で確かめた
- [x] 3.6 デモモードの編集画面で、上限を超える入力にエラーが出ることを確かめる（保存はいまどおり無効）
  - 確認結果: 最初は、保存を押したときだけ検証する作りのため、保存ボタンが無効のデモモードではエラーが出なかった（文字数の赤い表示だけ）。利用者と相談して検証のタイミングを `onTouched` にし、接続設定なしの開発サーバーのデモモードの編集画面で、料理名、説明、材料の行から離れると「料理名は100文字以内にしてください。」「ひとこと説明は500文字以内にしてください。」「材料は1行100文字以内にしてください（1行目）。」が出て、料理名を直すとそのエラーが消えることを DevTools Protocol（`focusout` を送って）で確かめた。保存ボタンはいまどおり無効
