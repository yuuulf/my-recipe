# Proposal

## Why

レシピノートの名前は作るときに決めたきり変えられない。`groups` テーブルには更新の RLS ポリシーがなく、画面にも名前を変える操作がない。複数のレシピノートを切り替えて使えるようになったので、名前で見分けやすいように、レシピノートのオーナーが名前を変えられるようにする。

## What Changes

UI の変更に加えて、データベースに名前を変える RPC を追加する（マイグレーション）。ルーティングは変えない。

- 設定画面のレシピノートの情報のカードで、オーナーはレシピノートの名前を変えられる
  - 名前の横の「名前を変更」から、その場で入力欄に切り替えて変える。保存とキャンセルができる
  - 空や空白だけの名前、50文字を超える名前は保存しない（作るときと同じ上限）
  - 保存すると、設定画面、サイドバーとスマホのヘッダーの切り替えの一覧など、名前を表示しているところがすぐ新しい名前になる
- オーナーでないメンバーには「名前を変更」を表示しない
- サーバー側でも、オーナーでない利用者が名前を変えることを拒否する（RPC でオーナーかを確かめる。画面のチェックだけに頼らない）
- 名前を変えるのは RPC だけにし、`groups` の更新の RLS ポリシーは追加しない（招待トークンや作成者など、名前以外の列を変えられないようにするため）
- デモモードでは「名前を変更」を表示しない

対象外:

- オーナーの交代、メンバーの役割の変更
- レシピノートからの退出、レシピノートの削除
- 名前の変更履歴
- 招待リンク（招待トークン）の作り直し

影響する動作モード:

- Supabase接続（手元では Supabase Local）: オーナーが設定画面から名前を変えられる
- デモ: 変わらない（名前の変更は表示しない）

## Capabilities

### New Capabilities

- `recipe-note-management`: レシピノートそのものの管理（いまは名前の変更）について、できる人、入力の制限、サーバー側の制限、デモモードでの扱いを定める。退出や削除などを足すときもここに置く

### Modified Capabilities

なし

## Impact

- 追加: `supabase/migrations/<タイムスタンプ>_add_rename_group.sql`（RPC `rename_group`。オーナーかの確認、名前の検証、名前だけを更新）
- 変更: `src/contexts/AppContext.tsx`、`src/contexts/app-context.ts`（名前を変える処理と、変えた後の `groups` と `group` の更新）
- 変更: `src/pages/SettingsPage.tsx`（名前の変更の操作）
- `seed.sql`: 変更なし（新しい RPC はサンプルのデータに影響しない。`npm run db:reset` で当たることを確かめる）
- RLS: `groups` のポリシーは変えない（更新は RPC だけ）
- localStorage のデータ形式: 変更なし
- 依存パッケージの追加: なし
- 本番: マイグレーションを本番の Supabase に当てる必要がある
