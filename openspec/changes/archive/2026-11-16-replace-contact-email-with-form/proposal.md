# Proposal

## Why

プライバシーポリシーと利用規約の「問い合わせ先」に運営者の個人のメールアドレスを `mailto` リンクで載せているため、だれでもアドレスを見られ、迷惑メールの対象にもなる。メールアドレスを公開せずに問い合わせを受けられるように、問い合わせ先を Google フォームに切り替える。

## What Changes

この変更は UI（文言とリンク）だけの変更で、データ・API・ルーティング・スキーマの変更は含まない。

- プライバシーポリシーと利用規約の「問い合わせ先」から運営者のメールアドレスと `mailto` リンクを取り除き、Google フォームへのリンク（新しいタブで開く）に置き換える。
- プライバシーポリシーの「情報の削除」の依頼方法を、問い合わせフォームから連絡する案内に変える。
- 問い合わせフォームで送られる内容（問い合わせ内容と、利用者が任意で書く返信先）を、プライバシーポリシーの「取得する情報」と「保存先」に追記する（Google フォームに保存される）。
- 両ページの最終更新日を更新する。
- フォームの URL は 2 ページで共有する 1 つの定数にまとめる。

利用者に見える効果: 問い合わせ先のメールアドレスが画面から消え、「問い合わせフォーム」のリンクから問い合わせる。

影響する動作モード: Supabase 接続モード（両ページは未ログインのまま開く）。デモモードはログイン後に入るモードのため確認の対象外とし、接続設定のない状態はどの URL でも接続設定の案内画面になる（app-modes の要件どおり）ため両ページは表示されない。Supabase は使わない。

### 対象外

- アプリ内の問い合わせ画面やデータベースへの保存（Google フォームを使うため作らない）。
- Git の履歴や過去のデプロイに残っているメールアドレスの消去。
- Google Cloud の OAuth 同意画面に登録したサポートメールなど、アプリの外の設定。
- Google フォームそのものの作成（運営者が作り、URL を実装に渡す）。

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `auth`: 「プライバシーポリシーと利用規約の表示」の要件に、問い合わせ先をフォームへのリンクで示しメールアドレスを載せないこと、フォームで受け取る情報をプライバシーポリシーに書くことを加える。

## Impact

- `src/pages/PrivacyPolicyPage.tsx`、`src/pages/TermsPage.tsx`: 問い合わせ先・情報の削除・取得する情報・保存先の文言、最終更新日、メールアドレス定数の削除。
- フォーム URL の定数を置く共通の場所（例: `src/lib/` 内）を追加する。
- 両ページのコンポーネントテストを追加する（いまはテストがない）。
- 外部依存: Google フォーム（運営者のアカウントで作成）。npm の依存は増えない。
