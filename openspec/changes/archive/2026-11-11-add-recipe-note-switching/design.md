# Design

## Context

目的と範囲は proposal.md、求める動きは specs/ を参照。ここでは、いまの作りのうち進め方に関わる点だけを書く。

- `AppContext.tsx` の `getSupabaseGroup` は、`group_members` を `created_at` の昇順で1件だけ読み、そのレシピノート（`groups(*)`）を `group` にしている。メンバーの一覧（`members`）はその1件について読む
- `createGroup` は RPC `create_group` の結果を `group` にする。`joinGroup` は RPC `join_group`（参加したレシピノートの ID を返し、すでにメンバーなら何もしない）の後に `getSupabaseGroup` を呼ぶため、2つ目に参加しても、いちばん古いレシピノートに戻ってしまう
- 一覧、検索（RPC `search_recipes` に `group.id` を渡す）、追加、設定画面は、すべて `group` を使う
- 詳細（`RecipeDetailPage.tsx`）と編集（`RecipeEditPage.tsx`）は、`recipe.group_id !== group.id` のときに「見つからない」にしている
- セットアップ画面（`SetupPage.tsx`）は認証だけを求め、所属している利用者も開ける。作った後は `/recipes` に移る
- サイドバー（`AppShell.tsx`）は「選択中のレシピノート」として頭文字と名前を表示している。スマホのヘッダーは `BrandLockup`（ロゴと「My Recipe」）と設定のボタンだけ
- RLS は、所属しているすべてのレシピノートのレシピと所属の行を読める（スキーマと RLS は変えない）
- 手元では、サンプルのレシピノートに招待で参加し、自分でもう1つ作れば、2つのレシピノートで確かめられる

## Goals / Non-Goals

**Goals:**

- 「開いているレシピノート」を1か所（`AppContext`）で持ち、ほかの画面はいままでどおり `group` を使えるようにする
- 選んだレシピノートを、アカウントごとに分けてブラウザに覚える
- 別のレシピノートのレシピの URL を開いたとき、「見つからない」を一瞬も出さずに切り替える

**Non-Goals:**

- URL にレシピノートの ID を入れること（URL の形は変えない）
- 切り替えの一覧での並べ替えや検索

## Decisions

### 1. `AppContext` に所属の一覧と切り替えを足す

```
AppContext
  groups:  Group[]       所属しているレシピノート（所属した日時の古い順）
  group:   Group | null  開いているレシピノート（いままでと同じ名前）
  members: GroupMember[] 開いているレシピノートのメンバー
  selectGroup(groupId)   開くレシピノートを替える（覚える）
```

- 読み込み: `group_members` を `user_id` で絞って `created_at` の昇順で全件読み、`groups(*)` を並べて `groups` にする。開くのは、覚えた ID が `groups` にあればそれ、なければ先頭（いまと同じ「いちばん古い」）
- `selectGroup` は `groups` にある ID だけを受け付け、`group` と `members` を替えて、ID を覚える
- `createGroup`: 作ったレシピノートを読み直した `groups` に入れ、それを開く
- `joinGroup`: RPC `join_group` が返す ID のレシピノートを開く（すでにメンバーでも同じ）。いまの「参加後にいちばん古いものを読む」処理はやめる
- デモモードは、いまどおり固定のレシピノート1つを `groups` と `group` にする

他の案: 開いているレシピノートを URL（例 `/notes/:id/recipes`）に持つ方法は、すべてのルートとリンクが変わるので使わない。

### 2. 覚える場所は localStorage、キーにアカウントの ID を入れる

- キー: `my-recipe:current-group:<user.id>`、値: レシピノートの ID
- アカウントの ID を入れるのは、同じブラウザで別のアカウントにログインしたときに、前の人の選択を使わないため
- 読み書きは `try/catch` で包む。使えないブラウザ（プライベートブラウズの制限など）では、覚えずにいちばん古いものを開く
- ログアウトしても消さない（次に同じ人がログインしたら同じレシピノートを開く）
- 覚えた ID が `groups` にないとき（外れた、削除された）は、先頭を開き、キーを先頭の ID に書き換える

### 3. 切り替えの一覧は1つの部品にして、サイドバーとヘッダーで使う

`src/features/groups/components/RecipeNoteSwitcher.tsx` を作る。

```
ボタン:  [我] 我が家のレシピ  (v)       <- 押すと一覧が開く
一覧:    +----------------------------+
         | (check) 我が家のレシピ      |
         |         友だちのレシピ      |
         |----------------------------|
         | +  新しいレシピノートを作る |  -> /setup
         +----------------------------+
```

- ボタンは `aria-haspopup="listbox"` と `aria-expanded` を持ち、一覧はボタンの下に重ねて出す（`absolute`、`z` はヘッダーより上）
- 一覧の外を押す、Esc を押す、どれかを選ぶと閉じる。開いているレシピノートには印（`Check`）を付ける
- 別のレシピノートを選んだら `selectGroup` の後に `/recipes` に移る。開いているものを選んだら閉じるだけ
- `variant`: `sidebar`（いまの「選択中のレシピノート」の見た目のまま、右に `ChevronDown`）、`header`（スマホのヘッダー用、文字を小さく、長い名前は省略）
- デモモード（`isDemoUser`）ではボタンにせず、名前を表示するだけにする
- 一覧の幅は、サイドバーでもヘッダーでも256pxにする。サイドバー（220px）に合わせると名前が省略され「新しいレシピノートを作る」が折り返すため、サイドバーでは本文の上に重ねて開く（PR のスクリーンショットで見て直した）

スマホのヘッダーは、左にいままでどおり `BrandLockup`（ロゴと「My Recipe」）、右端に `RecipeNoteSwitcher`（`header`）を並べる。いま右端にある設定のボタンは削除する（設定は下のメニューの「設定」から開けるため、同じ導線が重なっている）。

```
+--------------------------------------------+
| [logo] My Recipe     [我が家のレシピ  v]   |
+--------------------------------------------+
```

- `header` の見た目は、枠のある小さなボタン（`ChevronDown` 付き）にし、長い名前は省略する（`truncate`、最大幅はアプリ名と重ならない幅にする）
- 一覧は右端にそろえて、ボタンの下に開く
- 他の案: 設定のボタンの場所をハンバーガーメニューにする案は、開くまでいまどのレシピノートかが分からないので使わない。ヘッダーを2段にする案は、一覧に使える縦の幅が減るので使わない。一覧の見出しの上で切り替える案は、詳細や追加の画面でどのレシピノートかが分からないので使わない（利用者と相談して決定）

### 4. 詳細と編集は、別のレシピノートのレシピなら切り替えてから表示する

- レシピを読んだ後、`recipe.group_id !== group.id` で、`groups` にそのレシピノートがあれば `selectGroup(recipe.group_id)` を呼び、読んだレシピはそのまま表示する。`group` が替わってもう一度読み込みが走るが、同じレシピなので表示は変わらない
- `groups` にない（所属していない）場合は、RLS でそもそも読めないが、念のためいままでどおり「見つからない」にする
- 切り替えの間に「見つからない」を出さないよう、判定は `groups` を使い、`group` との違いだけでは「見つからない」にしない

### 5. セットアップ画面は、所属している利用者には「新しいレシピノートを作る」として出す

- `groups` が1つ以上あるときは、見出しを「新しいレシピノートを作る」にし、「ONE LAST STEP」の小見出しと初回向けの説明を出さない。カードの上に「戻る」（`/recipes`、開いていたレシピノートのまま）を置く
- 作った後は、決定1の `createGroup` で作ったものを開き、`/recipes` に移る（いまと同じ移動先）

### 6. 確かめ方

- 手元の Supabase Local で、サンプルのレシピノートに招待で参加し、セットアップ画面で自分のレシピノートを作ると、2つのレシピノートに所属した状態になる。この状態で、切り替え、再読み込み、別のレシピノートのレシピの URL、招待の再参加を確かめる
- 「覚えたレシピノートから外れた」場面は、Supabase Studio か `psql` で `group_members` の行を消して確かめる

## Risks / Trade-offs

- [切り替えた直後に、前のレシピノートの一覧の読み込みが遅れて返ってくる] → 一覧の読み込みは `group` が替わるたびに走り、古い結果は捨てる（いまの `active` のフラグの作りのまま）。切り替えの後に正しい一覧になることを確かめる
- [詳細を開いたまま別の端末でそのレシピノートから外された] → 次の読み込みで RLS により読めなくなり、「見つからない」になる。特別な扱いはしない
- [スマホのヘッダーから設定のボタンがなくなる] → 下のメニューの「設定」から開ける。設定画面への導線は1つになる
- [スマホでは長いレシピノートの名前が省略される] → 一覧を開けば全体が見える。390pxでおよそ8〜10文字まで表示する
- [localStorage を使えないブラウザ] → 毎回いちばん古いレシピノートを開く（いまと同じ動き）。切り替えはその間だけ効く
- [所属が多くなると一覧が長くなる] → 家族と友人で使う規模なので、今回は一覧の高さの上限（スクロール）だけ付ける
