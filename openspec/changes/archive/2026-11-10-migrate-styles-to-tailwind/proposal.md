# Proposal

**変更の種類:** UIのスタイルの実装のみ。画面の見た目と動作、データ、API、ルーティング、データベースのスキーマとRLS、localStorageのデータ形式は変更しない。

## Why

スタイルは `src/App.css`（約440行、約380のセレクタ）と `src/index.css` の手書きCSSで、独自のクラス名を介して約225か所の `className` から参照している。値のばらつきも多い。文字サイズは17種類あり、角丸には変数の他に `7px` や `20px` の直書きが残る。主色の透明度違いなど、変数を通さない色も約30種類ある。どのクラスがどの画面で使われているかも追いにくい。今後のデザインの修正に備え、Tailwind CSSに全面的に移行し、デザインの値をテーマに集めてばらつきを揃える。

## What Changes

- Tailwind CSS v4を導入し、Viteのプラグインで読み込む
- 色、影、角丸、フォント、ブレークポイントなど、`App.css` の `:root` の変数をTailwindのテーマに移す
- すべての画面と部品のスタイルを、`App.css` の独自クラスからTailwindのユーティリティクラスに書き換える
- `src/App.css` を削除する。`src/index.css` はTailwindの読み込みとテーマ、最小限のベーススタイルだけにする
- 画面ごとにずれている値（ほぼ同じ文字サイズ、直書きの角丸、変数を通さない色）を、見た目が変わらない範囲でテーマの値に揃える

### 利用者に見える効果

なし。見た目は移行前と同じにする。値を揃えることによる1〜2pxの差は許容するが、レイアウト、配色、表示される要素は変えない。

### 影響する動作モード

- **Supabase接続 / ローカルプレビュー / デモ:** すべての画面のスタイルが対象だが、どのモードでも見た目と動作は変わらない。モードごとの表示（デモの案内、ローカルプレビューの保存先の案内など）も移行の対象に含める

### 対象範囲

- `src/` 配下のすべての画面（ログイン、セットアップ、招待、レシピの一覧・詳細・登録・編集、グループ設定、プライバシーポリシー、利用規約）と共通部品
- スマートフォン表示とPC表示の両方

### 対象外

- 配色、レイアウト、文言の変更などのデザインのやり直し。移行が終わった後に別のchangeで行う
- ダークモードの追加
- UIライブラリ（shadcn/uiなど）の導入
- コンポーネントの構造の変更。スタイルの書き換えに必要な最小限の分割にとどめる
- 機能、データ、ルーティングの変更

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

なし。既存のspecは振る舞いを定めており、見た目と動作は変わらないため、specは変更しない（`.openspec.yaml` に `skip_specs: true` を設定する）。

## Impact

- **コード:** `src/index.css`、`src/App.css`（削除）、`src/main.tsx`、`vite.config.ts`、`src/components/` 配下、`src/pages/` 配下、`src/features/recipes/components/` 配下のすべてのコンポーネント
- **依存関係:** `tailwindcss` と `@tailwindcss/vite` を開発依存に追加する（`@tailwindcss/vite` 4.x はVite 8に対応している）
- **スキーマ:** 変更なし
- **ドキュメント:** `docs/DESIGN_IMPLEMENTATION_PLAN.md` は `App.css` とCSS変数を前提にしている。過去の計画として残すが、現在のスタイルの実装とは食い違うことになる
