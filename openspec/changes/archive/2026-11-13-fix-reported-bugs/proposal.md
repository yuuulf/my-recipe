# Proposal

## Why

利用者から報告された4つのバグと、それを調べる中で見つかった4つの問題を直す。どれも小さい修正だが、レシピの入力が消える、登録者を取り違えて見せる、英語のデータベースのエラーがそのまま出る、通信の失敗で新しいレシピノートを作らせてしまうなど、毎日使うときに困る・誤解を招くものが含まれる。

## What Changes

UI と状態の扱いの修正が中心。検索の修正のためにデータベースの関数を変える（マイグレーション）。ルーティングは変えない。

報告されたバグ:

1. レシピノートの読み込みに失敗したとき、未所属と同じくセットアップ画面に移ってしまう。失敗したときは、読み込めなかったことと、もう一度読み込む操作を表示する
2. レシピの詳細の「登録者」に、見ている人の名前が出る。登録した人の名前を出す（分からない場合は「メンバー」）
3. 検索語の `%` と `_` が、Supabase接続ではワイルドカードとして、デモでは文字どおりに扱われる。どのモードでも文字どおりに扱う
4. Supabase接続で、UUID の形でない ID のレシピの URL を開くと、データベースのエラーの文言が出る。「見つかりません」を出す

調べて見つかった問題:

5. 招待の URL のトークンが UUID の形でないと、データベースのエラーの文言が出る。「招待リンクが無効です」を出す
6. ログインのトークンが自動で更新されるたび（約1時間ごと、タブに戻ったときなど）にレシピノートを読み直し、その間は画面が読み込みの表示に替わるため、入力中のフォームの内容が消える。トークンの更新では画面を作り直さない
7. 設定画面で、メンバーを読み込む前やレシピノートを切り替えた直後に、オーナーの欄に見ている人の名前が、メンバー数に「0人」が出る。読み込むまでは表示しない
8. 編集画面で、別のレシピノートのレシピを開いてレシピノートを切り替えた後に、フォームの値を入れ直す。同じレシピなら入れ直さない

対象外:

- 上の8件以外の不具合や改善
- 読み込みに失敗したときの自動の再試行（もう一度読み込む操作を出すだけにする）
- 退会したメンバーの名前を表示すること（「メンバー」と表示する）

影響する動作モード:

- Supabase接続（手元では Supabase Local）: 1〜8のすべて
- デモ: 2（デモのレシピの登録者）と3（検索の扱いはいまと同じ文字どおり）。ほかは Supabase に関わるもので、デモの動きは変わらない

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `recipes`: 「レシピの詳細」に登録者の名前の表示を、「レシピの詳細」と「レシピの編集」に形が正しくない ID の場面を追加する
- `recipe-search`: 「キーワード検索」で、キーワードを文字どおりに扱う（`%` と `_` をワイルドカードにしない）ことを追加する
- `recipe-note-switching`: レシピノートの読み込みに失敗したときの表示を追加する
- `auth`: 「セッションの維持」に、トークンの自動更新で画面の入力が失われないことを追加する
- `recipe-note-management`: 無効な招待リンクの表示を追加する

## Impact

- 追加: `supabase/migrations/<タイムスタンプ>_escape_search_pattern.sql`（`search_recipes` でキーワードの `%`、`_`、`\` をエスケープする）
- 変更: `src/contexts/AppContext.tsx`、`src/contexts/app-context.ts`（読み込みの失敗の状態、トークンの更新で読み直さない）
- 変更: `src/App.tsx`（`GroupGuard` が失敗を未所属と区別する）
- 変更: `src/pages/RecipeDetailPage.tsx`（登録者、UUID の形の確認）、`src/pages/RecipeEditPage.tsx`（UUID の形の確認、入れ直さない）、`src/pages/JoinGroupPage.tsx`（UUID の形の確認）、`src/pages/SettingsPage.tsx`（読み込み前の表示）
- 変更: `src/features/recipes/api/recipes.ts`、`src/features/groups/api/groups.ts`（UUID の形の確認）
- デモのデータ（`src/lib/demoData.ts`）: 登録者の名前が出るよう、必要なら確認する
- スキーマ、RLS、`seed.sql`、localStorage のデータ形式: 変更なし（関数の中身だけ変える）
- 依存パッケージの追加: なし
- 本番: マイグレーションを本番の Supabase に当てる必要がある
