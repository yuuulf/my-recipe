## 4. 確認

- [x] 4.1 `npm run lint` と `npm run build` がエラーなしで通ることを確かめる
- [x] 4.2 Supabase Local で、レシピノートの読み込みに失敗したとき（ネットワークの遮断などで `group_members` の取得を失敗させる）、セットアップ画面に移らず、読み込めなかった旨と「もう一度読み込む」が出ること、通信を戻してボタンを押すと開いていたレシピノートが出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。テスト用のセッションでヘッドレスの Chrome を DevTools Protocol で操作し、`group_members` への通信を止めて `/recipes` と `/` を開いた。どちらもセットアップ画面に移らず、「レシピノートを読み込めませんでした」と「もう一度読み込む」が出た（postgrest-js が通信の失敗を3回まで自動で再試行するため、表示まで約7秒かかる）。通信を戻してボタンを押すと、`/recipes` に「サンプルのレシピノート」の一覧が出た。スマホ幅（390px）で見出しが「た」だけ折り返したため、「レシピノートを／読み込めませんでした」で折り返すようにした
- [x] 4.3 Supabase Local で、フォームに入力している間にトークンの更新（`supabase.auth.refreshSession()` などで `TOKEN_REFRESHED` を起こす）があっても、読み込みの表示に替わらず、入力した内容が残ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。メール（パスワード）のログインが無効で、手で作ったリフレッシュトークンもローカルの認証サーバーに拒まれたため、実際のトークンの更新は起こせなかった。代わりに、supabase-js がタブの間で使う BroadcastChannel から `TOKEN_REFRESHED` と `SIGNED_IN` のイベントを送り、アプリの `onAuthStateChange` に、更新のときと同じ形で届けた。レシピの追加画面で料理名と説明を入力した後に送っても、読み込みの表示は出ず（MutationObserver で監視）、入力した内容は残り、`group_members` の再取得は0件だった。変更前のコードで同じ手順を行うと、読み込みの表示が出て入力が空になり、再取得が4件あった
- [x] 4.4 Supabase Local で、ほかのメンバーが登録したレシピの詳細に、そのメンバーの名前が登録者として出ること、メンバーでない利用者が登録したレシピでは「メンバー」と出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。Supabase Local に、2人目のメンバー「ゆき」、メンバーでない利用者、それぞれが登録したレシピを足して確かめた。ゆきが登録したレシピの詳細は「登録者 ゆき」、メンバーでない利用者のレシピは「登録者 メンバー」、自分のレシピは「登録者 サンプル」と出た
- [x] 4.5 Supabase Local で、形が正しくない ID のレシピの詳細と編集の URL で「レシピが見つかりません」が出て、データベースのエラーの文言が出ないこと、形が正しくないトークンと、形は正しいが当たらないトークンの招待リンクで「招待リンクが無効です」が出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。`/recipes/abc` と `/recipes/abc/edit` は「レシピが見つかりません」が出て、データベースのエラーの文言もフォームも出なかった（形は正しいが存在しない ID も同じ）。`/join/abc` と、形は正しいが当たらないトークンの招待リンクは「招待リンクが無効です」と理由が出た（当たらないトークンは、途中で見つけた不具合を 3.3 の追記のとおり直した後）。正しい招待リンクでは、いままでどおりレシピノートの名前が出た
- [x] 4.6 Supabase Local で、レシピ一覧の検索に `_` や `%` を含む語を入れると、その文字を含むレシピだけが出ることを確かめる
  - 確認結果: 自動で確かめた（利用者と相談して決定）。レシピ一覧の検索欄に入力して確かめた。`_` と `a_b` は「記号テスト」だけ、`%` と `70%` は「カカオ70%チョコ」だけが出た。「卵」ではいままでどおり、卵を含むレシピが出た
