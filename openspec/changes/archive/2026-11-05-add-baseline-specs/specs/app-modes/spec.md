# Spec Delta

## Purpose

Supabase接続、ローカルプレビュー、デモの3つの動作モードについて、判定方法とレシピデータの扱いの原則を定める。認証とグループの振る舞いはこのspecの対象外とする。

## ADDED Requirements

### Requirement: 接続設定による動作モードの判定
システムは、Supabaseの接続先URLと公開可能キーの両方が設定されている場合にSupabase接続モードで動作しなければならない（SHALL）。どちらかが未設定の場合はローカルプレビューモードで動作しなければならない（SHALL）。

#### Scenario: 接続設定がある
- **WHEN** URLと公開可能キーの両方が設定された状態でアプリを起動する
- **THEN** システムはSupabaseのデータベースを使って動作する

#### Scenario: 接続設定がない
- **WHEN** URLまたは公開可能キーが未設定の状態でアプリを起動する
- **THEN** システムはローカルプレビューモードで動作する

### Requirement: クライアントへの秘密情報の非公開
service-roleキーなどの秘密情報をクライアントに公開してはならない（MUST NOT）。

#### Scenario: Supabaseへの接続
- **WHEN** クライアントがSupabaseに接続する
- **THEN** クライアントの設定に含まれるキーは公開可能キーのみである

### Requirement: ローカルプレビューのデータ保存
ローカルプレビューモードは、データをブラウザ内に保存し、初回起動時にサンプルのレシピを用意しなければならない（SHALL）。

#### Scenario: 初回起動
- **WHEN** 保存済みデータがないブラウザでローカルプレビューモードを起動する
- **THEN** サンプルのレシピを利用できる

#### Scenario: 再読み込み後のデータ保持
- **WHEN** ローカルプレビューモードでレシピを保存した後にページを再読み込みする
- **THEN** 保存したレシピが同じブラウザに残っている

#### Scenario: 保存先の案内
- **WHEN** ローカルプレビューモードで設定画面を開く
- **THEN** データがこのブラウザに保存される旨が表示される

### Requirement: デモモードの開始
システムは、デモ用の入口を開いたとき、またはURLに `demo=1` が指定されたときにデモモードを開始しなければならない（SHALL）。デモモードは接続設定の有無にかかわらず他のモードより優先されなければならない（SHALL）。

#### Scenario: デモ用の入口から開始
- **WHEN** 利用者が「デモのレシピを見る」を選ぶ
- **THEN** デモの固定データのレシピ一覧が表示される

#### Scenario: URLから開始
- **WHEN** `demo=1` を指定したURLでアプリを開く
- **THEN** 接続設定の有無にかかわらずデモモードで動作する

### Requirement: デモモードの継続
デモモードは、同じブラウザセッションの再読み込み後も継続しなければならない（SHALL）。

#### Scenario: 再読み込み
- **WHEN** デモモード中にページを再読み込みする
- **THEN** デモモードが継続する

### Requirement: デモデータの読み取り専用
デモモードは固定のデータを表示し、レシピの保存と削除を拒否しなければならない（MUST）。拒否された操作によってデータが変更されてはならない（MUST NOT）。

#### Scenario: 変更操作の拒否
- **WHEN** デモモードでレシピの保存または削除を実行する
- **THEN** 操作は完了せず、データは変更されない

#### Scenario: 固定データの案内
- **WHEN** デモモードで設定画面を開く
- **THEN** デモ用の固定データを表示している旨が表示される
