# Proposal

## Why

いまはレシピノートに一度参加すると抜けられず、オーナーも、参加してほしくない人や使わなくなった人を外せない。間違えて参加した、家族の構成が変わったなどのときに、レシピノートの一覧とメンバーの一覧に不要な人やレシピノートが残り続ける。

## What Changes

データ（RPC の追加）と UI の変更。テーブルの形とルーティングは変えない。

- **退出**: メンバーは、設定画面から開いているレシピノートを抜けられる。抜けた後は、所属しているほかのレシピノートを開く。ほかに所属していなければセットアップ画面に移る
- **オーナーの退出**: オーナーは、ほかにメンバーがいる間は退出できない（操作は出すが無効にし、理由を示す）。自分だけになったときは退出でき、そのときはレシピノートとそのレシピがすべて削除される。退出の前に、削除されることを確認する
- **メンバーの削除**: オーナーは、設定画面のメンバーの一覧から、ほかのメンバーをレシピノートから外せる。外す前に確認する
- **サーバー側**: 退出と削除は、新しい RPC でサーバー側の権限を確かめてから行う。メンバーを直接消す操作は、いまどおり RLS で拒否する
- **確認の画面**: 退出・削除・レシピの削除で同じ形の確認の画面を使うよう、共通の部品にまとめる

退出した人や外された人のレシピは、レシピノートに残る。登録者は、いまの仕様どおり「メンバー」と表示される。

対象外:

- オーナーをほかのメンバーに譲ること
- 招待リンクを作り直すこと（外された人も、同じ招待リンクを知っていれば参加し直せる）
- 外された人の画面への即時の反映（外された人の画面は、次に読み込んだときに反映される）
- オーナーが、ほかにメンバーがいるレシピノートを削除すること

影響する動作モード:

- Supabase 接続（手元では Supabase Local）: 退出と削除ができる
- デモ: 退出と削除の操作を表示しない

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `recipe-note-management`: レシピノートからの退出（オーナーの扱いを含む）と、オーナーによるメンバーの削除の要件を追加する

## Impact

- 追加: `supabase/migrations/<タイムスタンプ>_add_leave_and_remove_member.sql`（`leave_group`、`remove_group_member` の RPC）、`supabase/tests/` の pgTAP のテスト
- 追加: `src/components/ConfirmDialog.tsx`（共通の確認の画面）
- 変更: `src/contexts/AppContext.tsx`、`src/contexts/app-context.ts`（退出と削除の関数）、`src/pages/SettingsPage.tsx`（退出の操作、メンバーの削除の操作）、`src/pages/RecipeDetailPage.tsx`（確認の画面を共通の部品に置き換え）
- スキーマ（テーブル）、既存の RLS のポリシー、`seed.sql`: 変更なし
- 本番: マイグレーションを本番の Supabase に当てる必要がある
