# Design

## Context

目的と変える範囲は proposal.md を参照。ここでは、いまの作りのうち進め方に関わる点だけを書く。

- レシピ一覧は `RecipeListPage.tsx` が `grid grid-cols-1 sm:grid-cols-2 xl:grid-cols-3` でカードを並べている。カード（`RecipeCard.tsx`）は縦長で、右上の `ArrowUpRight`、`sm:min-h-47.5`、説明の2行省略を持つ。
- `AppShell` の `main` は `w-[min(1180px,100%)]` で、一覧以外の画面もこの幅を使っている。
- ロゴは `BrandLockup.tsx` の1か所で作っている。lucide の `Soup` を主色の四角に入れたもので、`full`（サイドバー、「レシピ管理」の小見出し付き）、`compact`（ログイン、招待、利用規約などの画面）、`header`（スマホのヘッダー）の3つの見た目がある。
- ファビコンは `public/favicon.svg` だけで、`index.html` が指定している。ページのタイトルと説明には「私のレシピ帳」とある。
- 用意されたロゴ画像 `src/logo.png` は 2000×2000、透過なし、背景は主色 `#347859` そのもの（約270KB）。
- 画像を加工できる道具は、macOS の `sips`（縮小のみ）と `swift`（CoreGraphics）がある。ImageMagick と Python の Pillow はない。
- 利用者に見える文言は、画面のファイルのほかに、`AppContext.tsx` と `features/recipes/api/recipes.ts` が投げるエラーにもある（「デモユーザーは〜できません」「グループ名を入力してください」など）。これらは画面にそのまま表示される。

## Goals / Non-Goals

**Goals:**

- 見た目の変更を Tailwind のユーティリティクラスと既存のトークンだけで行う
- 文言の統一を、利用者に見える文字列だけに対して漏れなく行う
- ロゴの画像を1つの部品（`BrandLockup`）だけで差し替え、使っている画面がそのまま追従するようにする

**Non-Goals:**

- コードの中の名前（`group`、`JoinGroupPage`、`features/groups/` など）の変更。呼び方を変えるのは画面に出る文字だけ
- `lib/localStorage.ts` のデモ用の表示名「デモユーザー」の変更（人の名前として表示されるもので、モードの呼び方ではない）
- `AppShell` の `main` の幅の変更

## Decisions

### 1. カードは1つのリンクの中に3行を組む

`Link` をカード全体のまま残し、中を次の3行にする。スマホを基準にし、PCでも同じ形を使う。

```
+--------------------------------------------------+
| 料理名（太字、長いときは折り返す）             > |
| 説明（1行で省略、値があるときだけ）              |
| #タグ #タグ #タグ #タグ          ⏱ 20分  👥 2人分 |
+--------------------------------------------------+
```

- 1行目: `flex items-start gap-3`。料理名は `min-w-0 flex-1`、右端は lucide の `ChevronRight`（`text-text-muted`、ホバーで `text-primary`）を `aria-hidden` で置く
- 2行目: `line-clamp-1`
- 3行目: `mt-auto flex items-end gap-3`。タグは `min-w-0 flex-1` の中で `tagRowClassName`（折り返しあり）を使い、時間と人数は `flex-none` で右に寄せる。タグがないときも時間と人数は右に寄せたままにする
- `ArrowUpRight`、`sm:min-h-47.5`、`order-*` のクラスは削除する
- ホバーの枠線と影の変化は残し、上へ1px動く動きはやめる（リストの行が上下に揺れて見えるため）

一覧のグリッド（`grid-cols-1`、`sm:grid-cols-2`、`xl:grid-cols-3`）はいまのまま残す。スマホでは1列の横長のリストになり、PCではいままでどおり2列か3列に並ぶ。グリッドでは同じ段のカードの高さがそろうので、3行目に `mt-auto` を付けてカードの下端にそろえる。

他の案: PCでも1列にして幅を760pxに絞る形は、実際に見ると横に長くて見づらかったので使わない。

他の案: 料理名の左にサムネイルを置く形は、画像の機能がないため使わない。

### 2. ロゴは縮めた画像を1つ用意し、角はクラスで丸める

- `src/logo.png` を `sips -Z 128` で 128×128 に縮め、`src/assets/logo.png` として置く。元の 2000px の画像はリポジトリに入れず、`src/logo.png` は削除する（元の画像は利用者の手元に残す前提）
- 128px は、いちばん大きく表示するログイン画面（40px 前後）の3倍の解像度まで足りる大きさ
- `BrandLockup` で `import logoUrl from '../assets/logo.png'` として `<img src={logoUrl} alt="" className="rounded-sm ...">` を表示する。角の丸め（6px）は `rounded-sm` のトークンで行い、画像には焼き込まない。アプリ名の文字が隣にあるので、画像の `alt` は空にする
- `Soup` のアイコンと主色の四角の `div` を削除する

他の案: 画像の角を加工して丸める方法は、表示する大きさごとに丸みが変わってしまうので使わない。

### 3. `BrandLockup` に `login` の見た目を足し、`full` の小見出しをなくす

| variant | 使う場所 | 画像 | アプリ名 |
|---|---|---|---|
| `full` | サイドバー | `size-8` | `text-16` |
| `compact` | 招待、利用規約など | `size-7.5` | `text-16` |
| `header` | スマホのヘッダー | `size-7.5` | `text-15` |
| `login`（新規） | ログイン画面 | `size-9`、`sm:size-10` | `text-28`、`sm:text-30` |

- `full` から「レシピ管理」の `span` と、名前を縦に並べる `div` を削除し、`compact` と同じ組み方にする（大きさだけ違う）
- `login` はカードの見出し「レシピノートをひらく」と同じ文字の大きさにする。トークンは既存の `text-28` と `text-30` を使い、新しいトークンは足さない

### 4. ファビコンは Swift の使い捨てのスクリプトで作る

- `public/favicon-32.png`、`public/favicon-16.png`: 元の画像を縮め、角を透過で丸める。丸みはどちらも一辺の約19%（32pxで6px、16pxで3px）にし、表示の `rounded-sm` と同じ見え方にする
- `public/apple-touch-icon.png`（180px）: 角を丸めず、透過もしない正方形にする。iPhone は自動で角を丸め、透過した部分は黒く塗るため
- 加工は scratchpad に置いた Swift のスクリプト（CoreGraphics で角丸のパスで切り抜いて PNG を書き出す）で行う。スクリプトはリポジトリに入れない
- `index.html` を次のように変え、`public/favicon.svg` を削除する

  ```html
  <link rel="icon" type="image/png" sizes="32x32" href="/favicon-32.png" />
  <link rel="icon" type="image/png" sizes="16x16" href="/favicon-16.png" />
  <link rel="apple-touch-icon" href="/apple-touch-icon.png" />
  ```

- `public/icons.svg` はファビコンではないので触らない

他の案: SVG に PNG を埋め込んで角丸に切り抜く方法は、ファイルが大きくなり、ブラウザによって表示が違うので使わない。

### 5. ログイン画面

スマホを基準にする。

```
スマホ                                 PC（lg 以上）
+---------------------------+         +-------------------------------------------+
| [logo] My Recipe (28px)   |         | [logo] My Recipe (30px)                   |
|                           |         |                                           |
| +-----------------------+ |         |  レシピをもっと手軽に     +-------------+ |
| | レシピノートをひらく  | |         |  管理・共有（主色、大）   | レシピノート| |
| | [Googleでログイン]    | |         |  説明文                   | をひらく    | |
| +-----------------------+ |         |  主な機能                 | [Google...] | |
|                           |         |  [本][虫][人][G]          +-------------+ |
| レシピをもっと手軽に      |         |                                           |
| 管理・共有                |         +-------------------------------------------+
| 説明文                    |
| [本]     [虫眼鏡]         |
| [人]     [G]              |
+---------------------------+
```

- ロゴ: `<BrandLockup variant="login" />`。ロゴが大きくなる分、スマホでカードと重ならないよう、画面の上の余白（いまの `pt-20.5`）を広げる。値は実際の画面で重ならない最小のものにする
- 見出し: `h2` の中を2つの `span`（`block`）に分ける。1行目は `text-17 lg:text-26`（いまと同じ）、2行目は `text-24 lg:text-38` と主色（`text-primary`）。`text-38` は既存のトークンを使う
- 主な機能: `ul` を `grid grid-cols-2 gap-3 xl:grid-cols-4` にし、各項目は縦に「アイコンの四角 → 機能名 → 説明」の順に並べる
  - 4つ横のとき、いちばん長い機能名「レシピノートの共有」（13pxで約117px）が1行に収まるよう、PCのアプリ説明の列の幅を 460px から 520px に広げる（1項目が約121px になる）
  - 4つ横にするのは `xl`（1200px）以上にする。`lg`（961px）から1200px未満の幅では、カードの列（470px）を引くとアプリ説明の列が520pxより狭くなり、機能名が折り返すため、2×2 のままにする
  - アイコンの四角: `grid size-11 place-items-center rounded-md bg-primary-soft text-primary`
  - アイコン: lucide の `BookOpen`、`Search`、`UsersRound`（22px）と、ログインボタンと同じ `GoogleIcon`
  - `GoogleIcon` に `size` の引数（いまの18pxを既定値）を足し、機能の一覧では22pxで使う
- 画面の下の飾りの文の `p` を削除する（招待画面も同じ）

### 6. 文言の置き換え表

利用者に見える文字列だけを変える。実装では、この表を見ながら1か所ずつ置き換え、最後に `grep` で「レシピ帳」「グループ」「ノート」「デモユーザーは」「デモ閲覧」が画面の文字列に残っていないことを確かめる。

## Risks / Trade-offs

- [ロゴを大きくしたログイン画面で、スマホの小さい画面（幅320px前後）でロゴとカードが重なる] → 上の余白を広げ、幅320pxと375pxで確かめる
- [16pxのファビコンで泡立て器の線がつぶれる] → 探索のときに見え方を確かめて許容した。気になる場合は後で16px用の画像だけ差し替えられる
- [元の 2000px の画像をリポジトリに入れないので、後で大きいサイズが必要になったときに作り直せない] → 元の画像は利用者の手元に残す。必要になったら別の変更で追加する
- [「レシピノート」に統一すると、エラーなどの文が長くなる] → 決めたとおり、短くするより表記をそろえることを優先する
- [置き換えの漏れ] → 決定6の `grep` で確かめ、3つの動作モードで主な画面を目で見る
- [ブラウザがファビコンを強くキャッシュし、変わっていないように見える] → 確認はキャッシュを消すか、シークレットウィンドウで行う
