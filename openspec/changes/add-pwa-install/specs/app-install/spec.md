## ADDED Requirements

### Requirement: アプリとしての追加
システムは、Web アプリマニフェストを提供し、対応するブラウザ（iPhone の Safari、Android の Chrome、PC の Chrome と Edge）からホーム画面またはデスクトップにアプリとして追加できなければならない（SHALL）。マニフェストには、アプリ名「My Recipe」、192px と 512px のアイコン、マスク可能なアイコン、テーマの色を含めなければならない（SHALL）。

#### Scenario: スマホのホーム画面に追加
- **WHEN** 利用者がスマホのブラウザで My Recipe を開き、ブラウザの機能でホーム画面に追加する
- **THEN** ホーム画面に My Recipe のアイコンと名前が追加される

#### Scenario: Android のアイコンの形
- **WHEN** Android で、端末の決まった形（丸など）でアイコンが表示される
- **THEN** ロゴが欠けずに表示される

### Requirement: アプリとしての起動
ホーム画面などから開いたアプリは、ブラウザのアドレスバーを出さずに表示しなければならない（SHALL）。開いたときは `/` から始め、ログインの状態とレシピノートの選び方は、ブラウザで開いたときと同じ規則に従わなければならない（SHALL）。アプリとして開いた状態でも、Google でのログイン、レシピの操作、デモを使えなければならない（SHALL）。

#### Scenario: アプリとして開く
- **WHEN** ログイン済みの利用者が、ホーム画面のアイコンから My Recipe を開く
- **THEN** アドレスバーのない画面で、開いていたレシピノートのレシピ一覧が表示される

#### Scenario: アプリとしてのログイン
- **WHEN** ログインしていない利用者が、アプリとして開いた画面で Google でログインする
- **THEN** ログインが終わると、アプリの画面に戻り、レシピノートを使える

### Requirement: 画面の端末への保存
システムは、アプリの画面を表示するためのファイル（HTML、JavaScript、CSS、画像）を端末に保存し、次に開いたときに使わなければならない（SHALL）。レシピ、レシピノート、メンバー、ログインに関わるデータを端末に保存して表示に使ってはならない（MUST NOT）。これらは、いままでどおり毎回サーバーから読まなければならない（SHALL）。通信がないときは、レシピを表示せず、読み込めなかったことを表示しなければならない（SHALL）。

#### Scenario: 通信がないときに開く
- **WHEN** ログイン済みの利用者が、通信がない状態でアプリを開く
- **THEN** アプリの画面は表示され、レシピノートを読み込めなかった旨と、もう一度読み込む操作が表示される

#### Scenario: ほかのメンバーの変更
- **WHEN** ほかのメンバーがレシピを変更した後に、利用者がアプリでそのレシピを開く
- **THEN** 変更後の内容が表示される

### Requirement: 新しい版への更新
新しい版がデプロイされた後にアプリを開くと、システムは新しい版を取得して自動で入れ替え、画面を読み直さなければならない（SHALL）。利用者に更新の操作を求めてはならない（MUST NOT）。

#### Scenario: デプロイの後に開く
- **WHEN** 新しい版がデプロイされた後に、利用者がインストールしたアプリを開く
- **THEN** 新しい版が取得され、画面が読み直されて新しい版が表示される
